# FSM停滞与起飞首轨迹可靠性修复

## 范围

本轮直接在既有`feat/high-view-liveness-20260919`分支继续，不另开分支。修复针对历史seed31–40确认的三类阻断：轨迹服务器保持但FSM不重规划、起飞高位首段在A*根节点失败、RETURN_HOME等动作没有首轨迹期限。没有改小膨胀、关闭水平障碍柱、放宽碰撞边界或释放门槛。

## 实现

1. **traj_server→FSM显式保持契约**
   - 服务器进展消息补齐当前`goal_seq`；FSM只接受与当前`goal_seq + traj_id + traj_start`完全一致且新鲜的SERVER消息。
   - `tracking_hold`持续0.25s才触发，瞬时保持会清零；每个轨迹代际最多触发一次。
   - 显式保持恢复和4s/4cm物理无进展共用同一目标级两次预算。服务器已在实测位置安全保持时，FSM先保留旧曲线并求新曲线；预算耗尽后发布`server_hold_budget_exhausted`，任务执行桥将其作为终端失败和取消处理。

2. **起飞首层可扩展性**
   - A*受约束首层在当前加速度之外增加一条朝目标方向、仍受原速度/占据/逐20ms碰撞检查约束的原语。它不允许穿过占据，也不改变后续完整加速度格重试。
   - 每次搜索记录起终点占据，以及闭集、速度、同体素、碰撞、同父节点剪枝、接纳和超时计数。初次与重试失败分别输出摘要，下一次seed32/34若仍失败可直接确定拒绝层。

3. **低空进场后升高**
   - 高位Probe新增可选`staging_xy`。启用后按“低空进场→同点升高→高位航线”执行；任一前置段失败都不能跳过后继续高位搜索。
   - 低空进场看到的目标不进入高位记忆；只有到达高位窗口或升高确认后才接收线索。
   - 缺目标时沿已验证的staging升降柱返回，不再错误标记起飞边界点为已验证升降柱。默认空配置保持旧行为，研究集成入口将显式配置场内点。

4. **所有规划动作的首轨迹期限**
   - 新增`execution/initial_plan_timeout`，覆盖SEARCH、RESUME、APPROACH、RETURN_HOME和ABORT；只有当前目标从未获得过有效轨迹时才计时。
   - 原`search_initial_plan_timeout`保留原语义，两个选项同时设置时必须一致。研究入口使用新参数，避免seed31在走廊RETURN_HOME继续等待90s。

## 离线验证

- 导航Python定向：77项通过，包含低空staging顺序/线索隔离、所有规划动作首轨迹期限、服务器保持耗尽终端处理。
- C++依赖闭包实际编译通过：`path_searching`、`plan_manage`及依赖；全工作区原始构建仍会被仓内ROS2版driver2和导航仓缺视觉包阻挡，因此按权威包闭包构建，未改系统环境。
- C++测试：65项、0失败。新增目标方向起步原语、占据起点诊断、SERVER身份/去抖/新鲜度、共享恢复预算测试；近目标/门洞和既有进展测试保持通过。
- Launch XML和`git diff --check`通过。

本轮没有启动SITL或实机。固定seed32/34首段、seed31走廊目标占据和0.25m跟踪保持注入仍需在集成分支完成定向动态验收；在这些结果出来前，只能称代码与离线契约修复完成，不能称停滞或起飞失败已动态根治。
